# HarpoonCannon model source

The user accepted **railgun C v4** on 2026-09-13. OBJ/MTL are the exact accepted
authored mesh and placeholder palette; `baseline.json` pins their SHA-256.
They contain no extracted game mesh, texture, or reconstructed Blueprint.
This directory is independent of the gameplay mod's older `SourceAssets`.

## Contents

- OBJ/MTL and `baseline.json`: accepted source checkpoint, centimeters, +X firing,
  +Y right, +Z up. Never silently overwrite this checkpoint for a new revision.
- `geometry.py`: mesh primitives and placeholder palette.
- `build_model.py`: complete generator, geometric audit, triangle/normal export,
  OBJ readback, and exact baseline hash verification.
- `render_model.py`: direct OBJ inspection with perspective-correct per-pixel
  depth, backface culling, and five reversed-draw-order checks.
- `prepare_handoff.py`: exact source hashes, complete base/yaw/pitch and six
  separate ammunition selections, pivot offsets and integration limitations.
- `runtime-model.json`: versioned importer contract with relative source paths;
  regenerated by the handoff script, owned by model work, not gameplay C++.

The old experimental generator chain was mechanically consolidated here.
Reproduction is verified against the original accepted OBJ/MTL bytes.
No script imports or needs the deleted scripts from `artifacts/`.

## Run from the repository root

Requires Python 3.10+, NumPy and Pillow. Rendering uses Windows Arial.
Use an existing Python environment containing those packages; no game, Unreal,
mapping, network access, or package installation is part of these commands.

```powershell
python models/HarpoonCannon/build_model.py
python models/HarpoonCannon/render_model.py
python models/HarpoonCannon/prepare_handoff.py
```

Build and render accept `--output <directory>`; pass the same directory to both. The default
is ignored `artifacts/modeling/HarpoonCannon`. A clean checkout can recreate it.
Output may not target this accepted source directory. Build checks mesh closure,
consistent winding, face planarity, nondegenerate triangles, magnet alignment,
socket attachment, export readback and exact accepted hashes. It fails on drift.
Do not run Python with `-O`, which disables geometry assertions.

Handoff defaults to `artifacts/modeling/HarpoonCannon/integration-v4/handoff.json`;
its `--output` selects the handoff directory. It reads the pinned source OBJ,
verifies hashes and geometric group coverage, and checks neutral reconstruction
and the six rods' identical local geometry. It neither changes source geometry
nor builds or installs a gameplay package.
The default invocation also verifies that `runtime-model.json` is byte-for-byte
current. After an intentional model-contract change, regenerate it with
`python models/HarpoonCannon/prepare_handoff.py --write-runtime-descriptor`.
Commit the descriptor together with the corresponding model source changes.

## Runtime descriptor schema 1

`runtime-model.json` is the stable integration entry point. Its structure is:

```text
schemaVersion: 1
units: "centimeters"
uniformScale: 1
axes: {forward: "+X", right: "+Y", up: "+Z"}
sources: {
  obj: {path: string, sha256: string},
  mtl: {path: string, sha256: string}
}
hierarchy: [{role, parentRole, locationRelativeToParentCm: [x,y,z]}]
meshes: [{role, meshOriginInSourceCm: [x,y,z], objectNames: [string,...]}]
ammo: {
  prototype: {role: "ammo", meshOriginInSourceCm: [x,y,z], objectNames: [string]},
  instances: [{name, parentRole: "yaw", sourceObjectName,
               locationRelativeToParentCm: [x,y,z]}]
}
sight: {parentRole: "pitch", locationRelativeToParentCm: [x,y,z]}  // optional
```

- Paths resolve relative to the descriptor directory, never cwd or an artifact
  directory. SHA-256 strings contain 64 uppercase hex characters and pin exact
  OBJ/MTL bytes. No game snapshot, absolute path, commit or release identity is
  part of this descriptor. Reject unsupported schema versions or hash mismatch.
- `hierarchy` is parent-first: roles `base`, `yaw`, `pitch` exactly once;
  parents are respectively `null`, `base`, `yaw`. Null means the existing
  gameplay-owned mount root. Each entry defines a component's neutral local
  translation. All neutral rotations are zero; scale is one. Yaw is about local
  Z; pitch uses UE Pitch (positive raises muzzle). Limits/input remain logic-owned.
- `meshes` selects source objects for exactly the three stable roles. Subtract
  `meshOriginInSourceCm` from each source vertex **once**, then apply component
  hierarchy translations to recover neutral assembly geometry. Origins are
  assembly-local; parent-relative translations are not interchangeable with them.
- `ammo.prototype` selects exactly one source object and uses the same recentering
  rule. Emit one shared ammo mesh, not six meshes. Six independent instances have
  stable names `ammo01` through `ammo06`, with local translations under yaw.
  `sourceObjectName` identifies each original rod for validation, not an additional
  mesh to bake. Prototype reconstruction matches all six source rods within
  1e-6 cm, including face topology and material identity.
- Base/yaw/pitch selections plus the six instance source objects cover the OBJ
  exactly once. Ammo is excluded from yaw geometry; the separate chambered rod
  remains in pitch. Engine asset/component identities belong to the importer,
  which maps these stable roles/names to them.
- Optional `sight` is an eye point above the rear breech, not at the muzzle or
  inside the bore. It inherits pitch with optical forward **local +X**, zero
  rotation offset: parallel to the bore axis, not converging toward the muzzle.
  For C v4 the breech top panel starts at X=-86 and reaches Z=149 cm. The point
  sits 6 cm forward of its rear edge, centered Y=0, with 5 cm vertical clearance:
  source **(-80,0,154)**, or **(-62,0,47) cm relative to pitch**. The script checks
  the conservative upper envelope of all OBJ parts within +/-10 cm in XY and
  a forward central strip +/-5 cm in Y; both retain at least 5 cm clearance in
  neutral assembly. The off-center optic at Y=-47..-33 lies outside that strip.
  This is not a full FOV/near-clip or moving-part clearance test; barrel visibility
  and camera settings require runtime validation. No second pivot subtraction
  is needed by the consumer. Absence means no model-supplied sight point; fallback
  belongs to logic. This additive schema-1 field replaces the former muzzle point.
- The descriptor deliberately contains no collision, materials implementation,
  aiming bounds, gameplay classes, stock-asset references or installation paths.
  Changing model object names, origins or offsets requires regenerating this
  file, not changing C++ allowlists. Schema/role changes require coordination.

Rendering produces `_hero.png`, `_inspection.png`, `_details.png` and a compact
`_render_audit.json`; building produces OBJ/MTL and `_audit.json`. Renderer failures
or changed source hashes must be investigated before changing the baseline.
Do not replace direct mesh renders with AI-generated images for geometry review.

## Model contract and pending work

- Fixed centered electricity inlet, yaw base, pitch assembly; standard game
  electricity mesh is still a placeholder and requires current-build validation.
- Five aligned top/left/right magnet stations, six independently named pointed
  rods; 9 cm diameter, 86 cm length. Visibility behavior remains logic-owned.
- 10 cm rail clearance; chamfered muzzle with 10 x 10 cm passage.
- Final UVs, materials, smoothing, pivot-motion clearances, Unreal import,
  construction preview and real-game appearance are not yet validated.
- Preserve gameplay source, collisions, camera/HUD/input, package and installation.
